Real-Life MLOps Pipeline

Full System Documentation & Orchestration Guide

📅 Last updated: March 23, 2026  •  🆔 DAG: real_life_mlops_pipeline

This pipeline simulates a production-grade Industrial IoT ML system. It automates the full lifecycle from data ingestion to containerized deployment, ensuring data quality via statistical tests and model excellence via performance gates.

Apache Airflow 3 MLflow PostgreSQL AWS S3 FastAPI Docker

1. System Architecture

The pipeline follows a robust sequential flow with multiple short-circuiting gates to maintain high standards of data and model integrity.

  • Ingests live sensor data from a streaming API.
  • Validates the data quality and statistical distribution (KS-Test).
  • Transforms raw readings into machine-learning features.
  • Trains a Logistic Regression anomaly detection model.
  • Deploys the model binary to AWS S3 if accuracy exceeds 75%.
  • Notifies stakeholders via SMTP Alerts for success/failure.

3. Environment Setup

3.1 Prerequisites

  • Docker Desktop (Windows) with WSL2 backend.
  • Python 3.9+ for running APIs locally.
AWS S3 Usage: The pipeline uses real AWS S3 (region: ap-south-1) via the aws_default connection. LocalStack is only for development/mocking of other DAGs.

3.2 Environment Variables (.env)

.env / ini
AIRFLOW_UID=50000 _PIP_ADDITIONAL_REQUIREMENTS=apache-airflow-providers-postgres mlflow scikit-learn pydantic # SMTP Email Alerts AIRFLOW__SMTP__SMTP_HOST=smtp.gmail.com AIRFLOW__SMTP__SMTP_PORT=587 AIRFLOW__SMTP__SMTP_USER=your@gmail.com AIRFLOW__SMTP__SMTP_PASSWORD=your_app_password # AWS Connection AIRFLOW_CONN_AWS_DEFAULT=aws://ACCESS_KEY:SECRET@/?region_name=ap-south-1
Pro Tip: Use a Gmail App Password (16-char) for SMTP, not your main password.

4. Task Breakdown

Task 1 — init_db_tables

Creates mlops_raw_sensor_data for readings and mlops_runs for audit logs.

Task 2 — ingest_live_sensor_data

Fetches 200 rows from the Mock API via host.docker.internal:8001.

Task 3 — wait_for_sensor_data

Custom sensor; polls every 10s. Blocks until 1+ row from the last hour arrives.

Task 4 — extract_raw_data

Combines new batch with 100k rows of historical mock data (Normal Dist, μ=50, σ=15).

Task 5 — check_data_drift

Uses Kolmogorov-Smirnov Test. Short-circuits if P-Value < 0.001.

Task 6 — transform_raw_data

Feature Engineering Logic:

ColumnFormulaPurpose
feature1value × 1.5 + N(0, 2)Linear scale + Noise
feature2value² / 100Polynomial
target1 if val > 75th % else 0Anomaly Label

Task 7 — train_and_log_model

Trains LogisticRegression, logs to MLflow registry, and pushes accuracy to XCom.

Task 8 — evaluate_model

Short-circuits deployment if accuracy < 75%.

Task 10 — upload_model_to_s3

Deploys to s3://mlops-production-models-bucket/models/logistic_model.pkl.

6. Mock IoT Sensor API

Runs on Port 8001. Simulates real-world sensor noise and intermittent anomaly spikes (5% chance).

bash
# Start the stream locally python mock_sensor_api.py

7. Model Serving API

FastAPI server on Port 8000. Downloads latest S3 model on startup.

bash
curl -X POST http://localhost:8000/predict \ -H "Content-Type: application/json" \ -d '{"feature1": 75.0, "feature2": 30.25}'

8. Docker Services Summary

Postgres: Port 5432 (Metadata + Data)
MLflow: Port 5000 (Registry)
Redis: Port 6379 (Task Broker)
Airflow UI: Port 8080

9. CI/CD Pipeline

GitHub Actions in .github/workflows/airflow_tests.yml runs pytest on every push to main, ensuring DAG integrity and task completeness.

10. Retry & Resilience

  • Retries: 3 attempts per task.
  • Delay: 5 minutes between retries.
  • Cleanup: cleanup_local_files runs all_done to prevent disk leaks.
